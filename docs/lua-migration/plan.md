# Lua 5.4 → Safe Rust: Full Port Plan

**Status:** Stage 3 IN PROGRESS — 2 of 7 commits landed (handle widening + generation bump). R1 retired. 183 tests green.
**Branch:** `feat/interactive-spike-lua`
**Scope:** Complete migration. No cuts. Drop-in ABI. See `docs/methodology/full-port-mode.md` for methodology and `memory/project_lua_full_port.md` for the seven lock-in decisions.
**Started:** 2026-04-11

## Ground truth

- C source: `noricum-spike-lua/*.c` + `*.h` (Lua 5.4 unmodified, 28,171 LOC across 37 files).
- Oracle: `wrapper.{c,h}` → `cc` static lib → `extern "C"` in `src/lib.rs`. `cargo test --test differential_lua -- oracle_selftest` must stay green.
- Diff-test corpus: `fixtures/lua_corpus/*.dat` (generated by `fixtures/gen_fixtures.py`, committed).
- Binary-size oracle: the C Lua reference binary compiled with `-Os` on the same system. Baseline for the 2× ceiling.

## The seven lock-in decisions (reference copy)

| # | Area | Choice |
|---|---|---|
| 1 | Dep budget | **ZERO** (`[dependencies]` empty, std allowed, `cc` as transitional build-dep only) |
| 2 | Errors | **`Result<T, LuaError>` threaded through every VM function** |
| 3 | GC | **Manual arena** (Vec slots + free list + generational indices + tri-color mark-sweep) |
| 4 | Coroutines | **CPS rewrite** of the VM dispatch loop |
| 5 | ABI | **Drop-in `extern "C"`** compatible with `liblua` |
| 6 | Bytecode | **Byte-exact compatible** with Lua 5.4 chunks |
| 7 | Seed | **piccolo — inspiration only**, cloned read-only to `/tmp/piccolo-ref`, no code copied |

Full rationale: `memory/project_lua_full_port.md`.

## Module-order dependency graph

```
Stage 1: Foundation  (leaf deps, depends only on std)
  llimits.h  →  type aliases, integer widths, bit sizes (NOT a module — inlined into types)
  lctype     →  ASCII character classification
  lzio       →  buffered input stream
  lopcodes   →  opcode enum + instruction encoding/decoding
  lmem       →  allocator interface (stubs GC hooks until Stage 3)

Stage 2: Types  (the type contract)
  contract.rs  →  TValue, LuaString, Table, Proto, LClosure, CClosure,
                  UpVal, UDataHeader, Thread, LuaState, LuaError
  lobject    →  TValue ops, typename lookups, GC header struct
  lstring    →  string table, interning (stub GC ties until Stage 3)
  lstate     →  global_State, thread state, stack layout
  ltm        →  tag method metadata + metatable dispatch
  lfunc      →  closure allocation, upvalue management

Stage 3: GC  (the big one)
  lgc        →  tri-color mark-sweep incremental GC, write barriers,
                 weak tables, finalizers, emergency collection
  [retrofit Stage 1-2 GC hooks at the end of this stage]

Stage 4: Tables + API  (the public surface starts here)
  ltable     →  hybrid array-part/hash-part, rehash, table iteration
  lapi       →  all lua_* C API functions (the drop-in surface, half)
  lauxlib    →  all luaL_* aux functions (the drop-in surface, other half)

Stage 5: Execution  (make Lua run)
  ldo        →  call/return, protected mode (lua_pcall innards),
                 error propagation (Result-threading enters here in earnest)
  lvm        →  bytecode interpreter (CPS-rewritten — the hardest module)
  ldebug     →  stack traces, runtime error messages, line-info lookups

Stage 6: Parser + compiler  (now we can validate against Stage 5)
  llex       →  lexer, token stream
  lparser    →  recursive-descent parser emitting intermediate form
  lcode      →  bytecode emitter — MUST BE BYTE-EXACT with C Lua's lcode.c

Stage 7: Serialization
  lundump    →  load precompiled chunks (.luac binary format, byte-exact)
  ldump      →  save precompiled chunks (.luac binary format, byte-exact)

Stage 8: Standard library
  linit      →  stdlib registration function
  lbaselib   →  base library (print, pairs, ipairs, type, tostring, etc.)
  lcorolib   →  coroutine.create/resume/yield — the CPS payoff
  lstrlib    →  string library (gsub, find, format — pattern matching is ~600 LOC alone)
  ltablib    →  table library (insert, remove, concat, sort, pack, unpack)
  lmathlib   →  math library (mostly std::f64 passthroughs)
  liolib     →  io library (file handles, read/write/seek)
  loslib     →  os library (time, date, getenv, execute)
  ldblib     →  debug library (introspection)
  lutf8lib   →  utf8 library

Stage 9: Dynamic loading
  loadlib    →  package.loadlib, require, path resolution, dlopen/LoadLibrary

Stage 10: Host binary
  lua.c      →  standalone interpreter (REPL + script runner)
```

## Risk register

Living list. Each risk gets a P(probability) × I(impact) score; mitigate highest first.

| # | Risk | P | I | Mitigation | Status |
|---|---|---|---|---|---|
| R1 | Manual arena silent use-after-free via slot reuse (freed handle derefs new occupant) | High | High | Generation counters on every handle; `free_*` bumps the counter; `alloc_*` stamps the current value; accessors panic on mismatch | 🟢 **retired 2026-04-11 (Stage 3 commit 2)** |
| R11 | `u32` generation counter wraps after 4B frees of the same slot → ABA bug | Low | High | `bump_generation` uses `checked_add` and panics on overflow with the "R11" marker message. Stage 3 v2 can widen to u64 if profiling ever hits it. | 🟡 active, mitigated via noisy panic |
| R2 | Bytecode drift between our `lcode.c` port and C Lua's original silently breaks the test suite | High | High | Byte-diff every compiled `.luac` against C Lua's output at every commit on Stage 6 | 🟡 plan documented, not enforced yet |
| R3 | CPS rewrite of `lvm.c` doesn't terminate / grows unbounded continuations | Medium | High | Prototype on 5-instruction subset first, validate shape before full port | 🔴 prototype not built |
| R4 | `Result`-threading fights with `lua_CFunction` signature (C callbacks expect `int (*)(lua_State*)` with longjmp escape) | High | Medium | Internal `lua_CFunction` returns `Result<i32, LuaError>`; `extern "C"` wrapper at the ABI boundary converts back to `int` with longjmp-like state flag | 🟡 known, design deferred to Stage 4 |
| R5 | `setjmp`/`longjmp` paths in the C oracle itself interact badly with Rust's unwinding during diff-test setup | Medium | Medium | Wrapper always uses protected calls (`lua_pcall`); never calls `lua_error` from a C function invoked by Rust | 🟢 Phase 0 already does this |
| R6 | Binary size creeps past 2× C baseline due to format! / panic machinery | Medium | Medium | Session-end size check, documented in plan doc | 🟡 check implemented, not yet enforced |
| R7 | Dynamic loading (`loadlib`) on Windows needs LoadLibraryA; cross-platform FFI layer without a crate is error-prone | Medium | Medium | Accept Unix-first; Windows support is a Stage 9 sub-milestone with its own testing | 🟡 acknowledged |
| R8 | `std::fmt` float formatting disagrees with Lua's `%g` for edge cases (nan, inf, -0, subnormals, precision edge) | High | Low | Hand-write `format_g()` port of `lua_Number` → string; validate against C Lua on a known-edge-cases fixture | 🟡 planned |
| R9 | UTF-8 surrogate-pair handling in `lutf8lib` differs between our impl and Lua's | Low | Medium | Port `lutf8lib.c` transcribing byte-for-byte first, then refactor | 🟢 low-priority |
| R10 | Pattern matching in `lstrlib` (Lua's `string.match` / `string.gsub`) has non-standard semantics that can't delegate to `regex` crate (anyway banned by ZERO); port must be byte-faithful | High | Medium | Transcribe `str_find_aux` + `match` logic 1:1 from C first, optimize later | 🟡 Stage 8 blocker |

## Decision log

Chronological. Every architectural call gets an entry.

- **2026-04-11 / 7 lock-ins:** ZERO / Result-threading / manual arena / CPS / drop-in / bytecode-compat / piccolo-inspiration-only. Operator call. See `memory/project_lua_full_port.md`.
- **2026-04-11 / std allowed under ZERO:** Operator confirmed that `std` is acceptable; "ZERO" means `[dependencies]` empty, not `no_std`. Binary target ~2× C baseline.
- **2026-04-11 / ltests.c excluded:** Lua's internal C test harness is replaced by our Rust test suite, not migrated. Saves 2,247 LOC of migration work for code that would be deleted after migration anyway.
- **2026-04-11 / lmem growth-strategy precondition:** `grow_array_size` documents and enforces `limit >= MIN_SIZE_ARRAY` as a debug_assert precondition. C Lua's `luaM_growaux_` has the same invariant but releases it as a no-op `lua_assert`, so the divergence was silent in C release builds. Diff-test earned-its-keep moment.
- **2026-04-11 / Mbuffer skipped in lzio:** Lua's `Mbuffer` (growable byte scratch buffer used by the lexer) is not ported — the Stage 6 lexer will use `Vec<u8>` directly. Every `Mbuffer` macro is a trivial `Vec` method.
- **2026-04-11 / Opcode and OpMode keep C names:** `OpCode` variants preserve the `OP_MOVE` / `OP_LOADI` / etc. spelling, and `OpMode` variants keep `iABC` / `ivABC` / etc. despite the Rust camelCase convention. Rationale: these are on-wire format identifiers documented with those exact names in the Lua 5.4 spec. Renaming creates a permanent decoder ring between the Rust port and the C source for every reader. Gated with `#![allow(non_camel_case_types, non_upper_case_globals)]`.
- **2026-04-11 / Div-by-zero error object is `TValue::Nil` placeholder:** Stage 2 `lobject::raw_arith` returns `Err(LuaError::Runtime(TValue::Nil))` on integer div-by-zero. Should be a TValue holding the "attempt to divide by zero" error string, but string interning had not landed in the contract at commit time. Stage 5 (ldo) will retrofit the real message when metamethod-aware arithmetic replaces the raw version.
- **2026-04-11 / LClosure upvalues pre-initialized eagerly:** `Heap::new_lclosure(proto, nupvals)` creates nupvals Closed(Nil) upvalues during allocation, fusing C's `luaF_newLclosure` + `luaF_initupvals` pair. The C split exists because of GC barriers that fire differently on uninitialized allocations; with manual arenas we don't need it yet and avoiding the "placeholder handle" window simplifies every Stage 5 call site.
- **2026-04-11 / Thread::open_upvals is unsorted in Stage 2:** C keeps `L->openupval` sorted descending by level for O(min(n, pos)) lookup during close. Our Rust port uses an unsorted `Vec<UpValHandle>`; profiling in Stage 5 can decide whether to sort. Semantics are identical, cost is `O(n)` per lookup where `n` is typically < 10.
- **2026-04-11 / `GlobalState::hash_seed` added to the contract:** Moved the hash seed from a per-call-site parameter to a field on `GlobalState` so `init_metamethod_names`, `intern_short`, and future stages share it without plumbing. Matches `global_State::seed` in `lstate.h`. Set by `LuaState::new(hash_seed)` at bootstrap.
- **2026-04-11 / `lobject::raw_arith` is separate from `luaO_arith`:** Ported just the raw arithmetic (no metamethod fallback). The `luaO_arith` wrapper that chains through `luaT_trybinTM` on non-numeric operands is Stage 4/5 because it needs `ltable::getshortstr` and VM frame machinery. Stage 2 callers use `raw_arith` directly and get `Ok(None)` for "try metamethod".
- **2026-04-11 / Handle field is `generation`, not `gen`:** Rust 2024 edition reserves `gen` as a keyword (for generators). The spike targets edition 2021 today but is a multi-week project that may migrate; name every handle field `generation` now to avoid a churn-only refactor later. Gated by `StringHandle::new(slot, generation) -> Self` constructor so the direct struct literal syntax stays rarely used.
- **2026-04-11 / `heap.rs` uses plain `assert!` not `debug_assert!`:** The checkpoint session caught that `cargo test --release` silently passed `double_free_panics_in_debug` because `debug_assert!` was a no-op. Double-free and access-after-free are programming errors that matter more in release than debug. Promoted all 8 free-side checks to `assert!` and renamed the tests. Cost: one `is_some()` + one `assert_eq!` per free. Worth it.
- **2026-04-11 / Stage 3 split into two sub-commits:** Commit 1 widens handles and adds the validation code path (always passes, since every generation is 0). Commit 2 wires the `bump_generation` call into `free_*` so the validation has teeth. Separating them means commit 1's retrofit is mechanically verifiable (176 → 178 tests, behavior-preserving) and commit 2's behavior flip is the one that adds the 5 new stale-handle tests. Also gives clean bisectability if a regression surfaces later.
- **2026-04-11 / `bump_generation` panics on u32 wrap (R11):** The free-side counter bump uses `checked_add(1).expect("generation counter wrapped (R11): ...")`. Wrap only happens after 4 billion frees of the same slot, which is not feasible in normal workloads. If it ever fires, the panic message names R11 and the operator can decide whether to widen to u64 in Stage 3 v2.
